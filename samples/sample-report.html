▲ HighConfigurationCVSS 7.5

Telnet is open

filesrv01.corp.example · 192.168.1.10:23/tcp

Telnet sends usernames, passwords and everything typed in plain text. Anyone on the network path can read them. Telnet on routers, switches and IoT devices is also a common target for botnets.

Evidence

TCP 23 accepted a connection; banner: Microsoft Windows XP telnetd

How to fix

  1. Disable the Telnet service on the device and use SSH instead.
  2. Windows: Disable-WindowsOptionalFeature -Online -FeatureName TelnetServer (older systems).
  3. Network gear (e.g. Cisco): 'line vty 0 15' → 'transport input ssh'.
  4. If Telnet can't be disabled, restrict it to a management VLAN with firewall rules.

▲ HighConfirmed

SMBv1 is enabled

filesrv01.corp.example · 192.168.1.10:445/tcp

The server still accepts SMB version 1, a 30-year-old file-sharing protocol with serious design flaws. Worms and ransomware such as WannaCry and NotPetya spread through SMBv1. Modern Windows, macOS and Linux clients don't need it.

Evidence

SMB1 NEGOTIATE offering only "NT LM 0.12" was accepted by the server.

How to fix

  1. Windows Server/PC (admin PowerShell): Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force
  2. Remove the feature completely: Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol (restart required).
  3. Across a domain: Group Policy › Computer Configuration › Administrative Templates › MS Security Guide › Configure SMBv1 server = Disabled.
  4. NAS / Samba devices: set the minimum SMB protocol to SMB2 (Samba: 'server min protocol = SMB2_10').
  5. Rescan this host to confirm the finding is resolved.

References

  • https://learn.microsoft.com/windows-server/storage/file-server/troubleshoot/detect-enable-and-disable-smbv1-v2-v3
  • https://www.cisa.gov/news-events/alerts/2017/03/16/smb-security-best-practices

■ MediumConfirmedCVSS 5.9

Weak TLS cipher suites accepted (RC4/3DES/DES)

192.168.1.20:443/tcp

The server accepts outdated ciphers. RC4 has known biases and 3DES is vulnerable to the SWEET32 birthday attack.

Evidence

Accepted: TLS_RSA_WITH_3DES_EDE_CBC_SHA (TLS 1.0)

CVE-2016-2183

How to fix

  1. Allow only AEAD suites with forward secrecy (ECDHE with AES-GCM or ChaCha20-Poly1305).
  2. Windows/IIS/RDP: disable old protocols and ciphers under HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL, or use IIS Crypto / a hardening GPO, then restart.
  3. Apache: SSLProtocol -all +TLSv1.2 +TLSv1.3 and SSLCipherSuite with modern AEAD suites.
  4. nginx: ssl_protocols TLSv1.2 TLSv1.3; ssl_ciphers with ECDHE+AESGCM/CHACHA20 suites.
  5. Appliances and printers: set the minimum TLS version in the device's web admin, and update its firmware if the option is missing.

References

  • https://ssl-config.mozilla.org/
■ MediumConfirmedCVSS 5.3

TLS 1.0 enabled

192.168.1.20:443/tcp

TLS 1.0 and 1.1 were formally retired in 2021 (RFC 8996). They rely on weak hashing and are no longer accepted by modern browsers.

Evidence

Server accepted ClientHello for: TLS 1.0. Supported overall: TLS 1.0, TLS 1.2.

How to fix

  1. Allow only TLS 1.2 and TLS 1.3.
  2. Windows/IIS/RDP: disable old protocols and ciphers under HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL, or use IIS Crypto / a hardening GPO, then restart.
  3. Apache: SSLProtocol -all +TLSv1.2 +TLSv1.3 and SSLCipherSuite with modern AEAD suites.
  4. nginx: ssl_protocols TLSv1.2 TLSv1.3; ssl_ciphers with ECDHE+AESGCM/CHACHA20 suites.
  5. Appliances and printers: set the minimum TLS version in the device's web admin, and update its firmware if the option is missing.
  6. Rescan to confirm.
